# המחותן — אפליקציית Android לניהול חתונה

אפליקציה מקומית (Local-first) לניהול ההכנות לחתונה: ספקים, התחייבויות, תשלומים, יתרות, משימות, לוח שנה ותזכורות, הסעות, מסמכים וקבלות, דוחות PDF, גיבוי ושחזור ונעילה בקוד PIN.
האפליקציה פועלת ללא אינטרנט, ואין לה בכלל הרשאת גישה לרשת.

- **applicationId:** `il.hamechutan.app`
- **גרסה:** ראו `version.properties` ו-`CHANGELOG.md`
- **minSdk 26** (Android 8.0) · **targetSdk 34**
- **שפה:** Kotlin 2.0.21, ממשק Android בלבד (ללא AndroidX)

---

## התקנה בטלפון

1. מעבירים את `HaMechutan-1.0.0.apk` לטלפון, למשל בהורדה, ב-WhatsApp לעצמכם או בכבל.
2. פותחים את הקובץ. בפעם הראשונה Android יבקש לאשר **"התקנה ממקור זה"** לאפליקציה שממנה נפתח הקובץ.
3. מתקינים ופותחים את **"המחותן"**.
4. בהגדרת התזכורת הראשונה מאשרים **התראות**. כדאי לאשר גם החרגה מחיסכון בסוללה (הגדרות ← תזכורות).

**עדכון גרסה:** מתקינים APK חדש מעל הקיים. העדכון יצליח רק אם ה-APK נחתם **באותו מפתח חתימה** (ראו "מפתח חתימה" בהמשך). הנתונים נשמרים בעדכון.

## עדכונים דרך GitHub

הקוד נמצא במאגר GitHub ציבורי. כל עדכון שנדחף לענף `main` עובר בנייה אוטומטית ב-GitHub Actions (`.github/workflows/build.yml`), שכוללת:
1. התקנת כלי הבנייה.
2. הרצת כל בדיקות היחידה.
3. בניית APK וחתימה **באותו מפתח חתימה**. המפתח שמור ב-Secrets של המאגר ואינו נמצא בקוד.

**פרסום גרסה חדשה:**
1. מעלים את `versionCode` ב-1 ומעדכנים את `versionName` בקובץ `version.properties`.
2. מוסיפים סעיף `## <גרסה>` בראש הקובץ `CHANGELOG.md`.
3. דוחפים ל-`main`. נוצר אוטומטית Release בשם `v<גרסה>` וקובץ ה-APK מצורף אליו.

**התקנת עדכון בטלפון:** פותחים את עמוד ה-Releases של המאגר ← הגרסה האחרונה ← מורידים את `HaMechutan-x.y.z.apk` ← מתקינים מעל הגרסה הקיימת. **הנתונים נשמרים.**

**Secrets נדרשים במאגר** (Settings ← Secrets and variables ← Actions):
- `KEYSTORE_BASE64`: התוכן של `release.jks` בקידוד base64.
- `KEYSTORE_PASSWORD`: הסיסמה (התוכן של `password.txt`).

## בניית ה-APK מחדש

הבנייה **אינה** משתמשת ב-Gradle, כי בסביבת הפיתוח המקורית Google Maven היה חסום. במקום זאת יש סקריפט שמפעיל ישירות את כלי Android הרשמיים: aapt2, Kotlin, R8, zipalign ו-apksigner.

```bash
# פעם אחת: התקנת כלי הבנייה (Ubuntu 24.04) לתוך /opt/tc
./tools/setup-toolchain.sh

# הרצת כל בדיקות היחידה (לוגיקה עסקית, מסד נתונים, גיבוי, דוחות, PIN)
./tools/run-tests.sh

# בניית APK חתום
./build.sh            # → build/outputs/HaMechutan-1.0.0.apk
```

- **שינוי גרסה:** בקובץ `version.properties` בלבד. מסך "אודות" ו-Gradle קוראים את הגרסה משם.
- **מפתח חתימה:** `build.sh` משתמש ב-`signing/release.jks` ובסיסמה שב-`signing/password.txt`. אם התיקייה לא קיימת, נוצר מפתח חדש. **כדי לעדכן אפליקציה שכבר מותקנת חייבים להשתמש באותו מפתח.** לכן שמרו את חבילת החתימה שנמסרה בנפרד, והעתיקו אותה לתיקייה `signing/` לפני הבנייה. אפשר גם להגדיר מיקום אחר עם `SIGNING_DIR=/path ./build.sh`.
- **Android Studio:** צורפו `settings.gradle.kts`, `build.gradle.kts` ו-`app/build.gradle.kts` סטנדרטיים. **הם לא נבדקו בסביבה המקורית.** הקוד אינו תלוי ב-AndroidX, ולכן הבנייה ב-Gradle אמורה להיות פשוטה.

### החלטות מרכזיות

- **סכומים** נשמרים באגורות (מספר שלם), ולכן אין שגיאות עיגול.
- **התחייבות** היא רשומת `expense` אחת. כל **תשלום** הוא רשומה נפרדת בטבלת `payment`, מסוג תשלום או החזר.
  - הסכום ששולם, היתרה, המצב ותאריך התשלום האחרון **מחושבים תמיד מהתשלומים** ולא נשמרים פעמיים.
  - ספק מקושר להתחייבויות שלו, ולכן התחייבות אינה נספרת פעמיים.
- **פעולות כספיות** שמשנות כמה רשומות רצות בטרנזקציה אחת.
  - יש מפתחות זרים ובדיקות CHECK ברמת מסד הנתונים.
  - יומן שינויים (`audit_log`) מתעד עריכה ומחיקה של תשלומים, שינויי מחיר וביטולים.
- **מחיקות:**
  - אי אפשר למחוק ספק או הוצאה שיש להם היסטוריה כספית. אפשר לבטל אותם במקום, וההיסטוריה נשמרת.
  - מחיקת תשלום מחייבת אישור ונרשמת ביומן.
  - פריטים מקושרים (משימות, מסמכים) נשמרים ומנותקים מהפריט שנמחק.
- **ביטול התחייבות:** מבקשים כמה כסף הוחזר.
  - ההחזר נרשם כרשומת החזר.
  - מה שלא הוחזר נחשב לעלות בפועל.
- **תזכורות:**
  - הליבה מחשבת אילו התראות צריכות להיות מתוזמנות.
  - `ReminderScheduler` מסנכרן אותן מול AlarmManager אחרי כל שינוי, ושומר מה תוזמן בפועל.
  - הממשק מציג "מתוזמנת" **רק** כשההתראה אכן תוזמנה במכשיר. אחרת מוצגת הסיבה: התראות חסומות, אין מועד, המועד עבר, תזמון לא מדויק ועוד.
  - סנכרון מחדש מתבצע אחרי הפעלה מחדש של הטלפון, עדכון גרסה, שינוי שעה או אזור זמן ושינוי הרשאה.
- **גיבוי:** קובץ ZIP הכולל:
  - `manifest.json`: גרסאות, ספירות ו-SHA-256 לכל קובץ.
  - `data.json`: כל הטבלאות לפי שמות עמודות.
  - `files/`: **הקבצים המצורפים עצמם**.

  שחזור מתחיל בבדיקה מלאה ורק אחריה מחליף נתונים. ההחלפה מתבצעת בטרנזקציה אחת עם בדיקת מפתחות זרים. בכל כשל הנתונים הקיימים נשארים כפי שהיו. לפני שחזור נשמר גיבוי אוטומטי של המצב הנוכחי.
- **רב-חתונתיות בעתיד:** כל הרשומות משויכות ל-`wedding_id`.

### מגבלות ידועות

- ב-Android 12 ומעלה, אם לא ניתנה הרשאת "תזמון מדויק", התזכורות מתוזמנות באופן משוער. האפליקציה מציגה זאת במפורש.
- "עצירה בכוח" של האפליקציה מהגדרות Android מבטלת את כל ההתראות עד לפתיחה הבאה של האפליקציה. זו התנהגות של Android.
- יצרנים מסוימים (למשל Xiaomi ו-Huawei) מגבילים אפליקציות ברקע. מומלץ להחריג את האפליקציה מחיסכון בסוללה.
- תצוגת PDF בתוך האפליקציה מוגבלת לעמודים הראשונים. את המסמך המלא פותחים באפליקציה חיצונית.
