# שרת הרישיונות של "המחותן"

השרת הוא Google Apps Script שמחובר לגיליון Google Sheets. כל לקוח הוא שורה בגיליון **"לקוחות"**, ומנהלים את כולם מתפריט **"רישיונות"** שבגיליון.
השרת חינמי ורץ בחשבון Google שלכם.

| עמודה | משמעות |
|---|---|
| שם משתמש | מה שהלקוח מקליד. מומלץ: מספר הטלפון שלו. רווחים ומקפים לא משנים (`050-123 4567` זהה ל-`0501234567`). |
| סטטוס | `פעיל` או `חסום` |
| תוקף עד | לא חובה. אחרי התאריך הזה המנוי נעצר (התאריך עצמו עוד תקף). |
| טלפון מחובר | דגם הטלפון שהחשבון פעיל בו. ריק = פנוי לכניסה מטלפון חדש. |
| הופעל בתאריך / נראה לאחרונה / גרסה | מתעדכנים אוטומטית |
| הערות | לשימושכם: שם הלקוח, תשלום וכו׳ |

עמודות מוסתרות: מזהה המכשיר, וגיבוב הסיסמה עם מלח (`hash`, `salt`). **הסיסמאות עצמן לא נשמרות בשום מקום**, ולכן אי אפשר לשחזר סיסמה, רק לאפס אותה.

---

## הקמה (פעם אחת)

**הקובץ להדבקה** הוא העותק האישי `license-keys/Code.gs`, שנוצר בעזרת `tools/license-keys.sh`. הוא זהה ל-`Code.gs` שבמאגר, בתוספת המפתח הפרטי לחתימת התשובות. **אל תשתפו את הקובץ הזה, ואל תכניסו אותו למאגר.**

1. פותחים גיליון חדש: https://sheets.new וקוראים לו, למשל, "המחותן – לקוחות".
2. בתפריט: **הרחבות** (Extensions) ← **Apps Script**.
3. בעורך שנפתח מוחקים את כל מה שכתוב בקובץ `Code.gs`, מדביקים את כל תוכן הקובץ האישי ושומרים (Ctrl+S).
4. **פריסה** (Deploy) ← **פריסה חדשה** (New deployment). ליד "Select type" לוחצים על גלגל השיניים ובוחרים **אפליקציית אינטרנט** (Web app):
   - **Execute as:** Me
   - **Who has access:** Anyone
   - לוחצים **Deploy**.
5. Google יבקש לאשר גישה: **Authorize access** ← בחירת החשבון.
   - אם מופיע "Google hasn't verified this app": לוחצים **Advanced** ← **Go to … (unsafe)** ← **Allow**.
   - זה הסקריפט שלכם, והאזהרה מופיעה לכל סקריפט פרטי.
6. מעתיקים את הכתובת שמופיעה תחת **Web app**. היא מסתיימת ב-`/exec`. את הכתובת הזו מכניסים לאפליקציה:
   ```bash
   ./tools/license-keys.sh https://script.google.com/macros/s/<id>/exec
   ```
7. חוזרים לגיליון ומרעננים את הדף (F5). אחרי כמה שניות מופיע התפריט **רישיונות**. בוחרים בו **הכנת הגיליון**.
8. **בדיקה:** פותחים את כתובת ה-`/exec` בדפדפן. אמורה להופיע השורה `{"ok":true,"service":"hamechutan-license","protocol":1}`.

## עבודה יומיומית (תפריט "רישיונות")

- **לקוח חדש:** "הוספת לקוח" ← שם משתמש ← הערות.
  - הסיסמה (8 ספרות) נוצרת אוטומטית ומוצגת **פעם אחת**, יחד עם הודעה מוכנה לשליחה ללקוח.
- **הלקוח עבר לטלפון חדש:** מסמנים תא בשורה שלו ← "שחרור הטלפון של הלקוח המסומן".
  - הטלפון הישן מתנתק בבדיקה הבאה שלו.
  - הלקוח יכול להתחבר מהחדש עם אותם פרטים.
- **הלקוח שכח את הסיסמה:** מסמנים את השורה ← "איפוס סיסמה ללקוח המסומן". הטלפון שלו ממשיך לעבוד, ואין צורך להתחבר מחדש.
- **הפסקת מנוי:** "חסימה / ביטול חסימה", או תאריך בעמודה "תוקף עד".
  - האפליקציה של הלקוח תינעל בבדיקה הבאה: בפתיחה עם אינטרנט, ולכל המאוחר אחרי 7 ימים בלי אינטרנט.
  - **הנתונים שלו לא נמחקים**, וחוזרים כשהמנוי מתחדש.

אפשר גם לערוך את הגיליון ישירות (סטטוס, תוקף, הערות). **לא לערוך** את העמודות המוסתרות.

## עדכון קוד השרת

1. מכינים את העותק האישי המעודכן: `./tools/license-keys.sh` (המפתח הקיים נשמר).
2. מדביקים את התוכן ב-Apps Script במקום הקוד הקיים ושומרים.
3. **פריסה** ← **ניהול פריסות** (Manage deployments) ← עיפרון ← **Version: New version** ← **Deploy**.

⚠️ אל תיצרו "פריסה חדשה" לצורך עדכון. פריסה חדשה מקבלת כתובת אחרת, והאפליקציות שכבר אצל הלקוחות לא יכירו אותה.

## אינטרנט מסונן

לקוחות עם נטפרי, רימון או אתרוג עלולים לקבל באפליקציה את ההודעה "לא התקבלה תשובה תקינה משרת המנויים".
- הפתרון: לבקש מחברת הסינון לאשר את `script.google.com` ואת `script.googleusercontent.com`.
- האפליקציה סומכת על תעודת הסינון שהלקוח התקין. כל תשובה של השרת חתומה, ולכן הסינון יכול לחסום את הבדיקה, אבל לא לזייף אישור.

## בדיקות

- `node --test server/license/test/*.test.js`: בדיקות היחידה של `Code.gs` מול גיליון ושירותי Google מדומים.
- `tools/run-tests.sh`: מריץ גם את השרת האמיתי מעל HTTP, כולל הפניה (302) כמו ב-Google, ומבצע מולו בדיקה מקצה לקצה של קוד הרישוי באפליקציה.
